# Publishing ShareInbox

Repository: https://github.com/bawantha/shareinbox-kmp

First published release: `io.github.bawantha:shareinbox:0.1.0-alpha01`.
This version is available on Maven Central. It is an alpha: physical-device share-sheet validation remains outstanding (see TDD.md).

## One-time account setup

1. Sign into https://central.sonatype.com/ with your GitHub account. Verify that `io.github.bawantha` is listed as a verified namespace. Follow https://central.sonatype.org/register/namespace/ if it is not.
2. Generate a Central Portal publishing user token. Its generated username and password are distinct from your website credentials.
3. Create an artifact-signing GPG key and publish its public key as described in https://central.sonatype.org/publish/requirements/gpg/ . Keep its private key private.
4. Add these GitHub Actions repository secrets under Settings → Secrets and variables → Actions:
   - `MAVEN_CENTRAL_USERNAME`: token username
   - `MAVEN_CENTRAL_PASSWORD`: token password
   - `SIGNING_KEY`: ASCII-armored private signing key
   - `SIGNING_PASSWORD`: signing key passphrase

Never put credentials in source files, issues, chat, or build logs.

## Verify and publish

The `Publish to Maven Central` workflow is manually dispatched on `main`. It checks credentials, runs platform tests, publishes all targets locally, verifies an independent consumer, then signs and uploads the release to Central. It uses the version committed in `gradle.properties`; Central releases are immutable. Check the normal Verify workflow and remaining manual test checklist before dispatching.

For local verification without credentials:

```sh
./gradlew :shareinbox:publishAllPublicationsToLocalBuildRepository
./gradlew -p verification/consumer jvmTest compileCommonMainKotlinMetadata compileKotlinIosSimulatorArm64
```

To publish from an appropriately configured local environment:

```sh
./gradlew :shareinbox:publishAndReleaseToMavenCentral -PreleaseToCentral=true
```

The plugin reads `ORG_GRADLE_PROJECT_mavenCentralUsername`, `ORG_GRADLE_PROJECT_mavenCentralPassword`, `ORG_GRADLE_PROJECT_signingInMemoryKey` and `ORG_GRADLE_PROJECT_signingInMemoryKeyPassword`. Signing and remote publication are enabled only with `releaseToCentral=true`. Local builds need no secrets. Sources and documentation JARs are generated by the publishing plugin; the documentation JAR is a placeholder, with API usage documented in the repository.

## klibs.io

klibs.io is a catalog, not a package host. After Central publication:

1. Confirm the exact release is available in Google's Maven Central mirror. For this release the POM is https://maven-central.storage-download.googleapis.com/maven2/io/github/bawantha/shareinbox/0.1.0-alpha01/shareinbox-0.1.0-alpha01.pom . Mirror propagation has no guaranteed deadline.
2. The KMP publication must include `kotlin-tooling-metadata.json`; its POM must identify this public GitHub repository. Both are included by this build.
3. Allow automatic discovery or use the indexing request linked from https://klibs.io/faq . Do not submit before the mirror contains the release.
4. Check https://klibs.io/package/io.github.bawantha/shareinbox/0.1.0-alpha01/status .

Update README's availability statement only once Central publication succeeds.
